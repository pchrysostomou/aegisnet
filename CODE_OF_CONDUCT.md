# Code of Conduct

## The short version

Be decent to people. Argue with the work, not with whoever produced it.

This is a small, public, defensive-security project. It is here to be read and checked, so the
thing that matters most is that people feel able to say "this claim is wrong" without it becoming
personal in either direction.

## What is expected

- **Disagree about the substance.** "This says the URL is fetched and nothing fetches it" is the
  most useful sentence anybody can write here. Bring the file and the line.
- **Assume the other person is trying.** Most wrong claims in this repository were written by
  somebody who believed them at the time; several are recorded in `CHANGELOG.md` for exactly that
  reason.
- **Accept a correction plainly.** Fix it, say what was wrong, move on.
- **Respect the scope.** This project is defensive only. Requests for scanning, exploitation or
  automated response are out of scope regardless of how they are framed, and saying so is not
  hostility.

## What is not acceptable

Harassment, personal attacks, demeaning or discriminatory comments, sustained disruption,
publishing anybody's private information, or unwelcome attention of any kind. Also: using this
repository or its issues to solicit or share offensive tooling.

This applies to issues, pull requests, commit messages, code review and anywhere else the project
is being discussed.

## Reporting

Report a problem to the maintainer, [@pchrysostomou](https://github.com/pchrysostomou), through
GitHub — a private vulnerability report on this repository is the most private channel available
here, and is fine to use for a conduct issue as well. Please do not open a public issue about
somebody's behaviour.

Reports are read by the maintainer alone. What happens next depends on what happened, and ranges
from a private word to blocking an account and removing the content. If your report concerns the
maintainer, GitHub's own [reporting
process](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam)
exists for that and does not go through this repository.

## Scope and attribution

This applies in all project spaces and when somebody is representing the project elsewhere.

Adapted from the [Contributor Covenant](https://www.contributor-covenant.org), version 2.1,
shortened to what a single-maintainer project can actually promise to do.
